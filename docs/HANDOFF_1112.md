# 11/11~11/12 고친 것 정리 (음성 구조 변경 + 휴게소 제안)

## 왜 바꿨나
11/11 주최측 답변:
> 음성 기능(읽어 주기, 음성 인식, **마이크 사용**)은 **Pleos 문서에 안내된 방식으로만** 구현해야 한다.

Pleos 문서에는 **녹음해서 파일로 저장하는 방법이 없다.** STT SDK는 글자만 돌려주고, 권한도 `STT_SERVICE` 하나뿐이다. 그래서 **목소리 녹음은 전부 빼고**, 아래처럼 바꿨다.

> 가족이 **말로** 대답 → **Pleos STT**가 글자로 바꿈 → **글자로 저장** → 다시 지나갈 때 **Pleos TTS**가 읽어 줌

## 1. 녹음 → STT·TTS 구조 (11/11)
- **녹음 코드 삭제**
  - `RECORD_AUDIO` 권한 삭제 (Manifest)
  - `VoiceTester.kt` 파일 삭제
  - 마이크 녹음 함수(`askQuestion`, `toggleRecording` 등) 삭제
- **`Memory`에 `text` 추가** (`MemoryStore.kt`): 대답을 글자로 저장한다. 오디오 파일은 이제 없다.
- **`PleosVoice.kt`**
  - TTS: `speak(text) { ok -> }`
  - STT: `listen { heard, ok -> }`
  - 테스트용 ON_DEVICE / HYBRID 연결 함수 추가
- **`MainActivity.kt`**
  - `say(text, clip)`: 차가 말하기. Pleos TTS가 안 되면 시연용 소리 파일(clip)을 틀고, 그것도 없으면 조용히 넘어간다.
  - `listenFamily(...)`: 가족 대답 듣기. 시연 모드에서는 미리 정한 문장으로 대신한다.
  - 질문 → 삐 → 대답 → 글자 저장 → "좋아요. 이 장소에 잘 남겨둘게요." 순서
- **새 파일 `DemoSpeech.kt`**: 시연 때 쓸 정해 둔 문장(가족 대답 3개, 작년 이야기 등)

## 3. ⭐ 휴게소 다가가면 차가 먼저 제안 (11/12, 새 기능)
시연 천안 장면: 휴게소 3km 앞에서 아래 순서로 진행된다.
1. **차**: "곧 천안삼거리휴게소예요. 작년에 여기서 호두과자가 진짜 맛있다고, 내년에 또 사 먹자고 하셨죠. 들렀다 갈까요?"
2. 삐
3. **가족**: "응!" (시연: `demo_reaction_cheonan` 소리)
4. **네비에 휴게소를 경유지로 추가** (Pleos NaviHelper `addWaypoint`)
5. **차**: "좋아요. 천안삼거리휴게소를 경유지로 넣었어요."

가족이 "아니"라고 하거나 대답을 못 알아들으면 "알겠어요. 그냥 지나갈게요."로 끝나고 경로는 그대로다.

| 단계 | 쓰는 것 | 상태 |
|---|---|---|
| ① 시점 잡기 | 앱 (위치) | 동작 |
| ② 문장 만들기 | **Pleos LLM SDK** `generateContent` | 연동 코드 있음. 5초 안에 답이 없으면 정해 둔 문장 틀 사용. 시연은 예시 문장(`DemoSpeech.SUGGEST_LINE`) |
| ③ 말하기 | Pleos TTS | 시연은 소리 파일 |
| ④ 대답 듣기 | Pleos STT | 시연은 소리 파일 |
| ⑤ 경유지 추가 | **NaviHelper `addWaypoint`** | 연동 완료. 실제로 되는지 확인 필요 |

- 실제 운전 중(시연 아님)에도 예전 여행 장소에 가까워지면 같은 흐름이 돈다.
- 끄려면 `VoiceRules.SUGGEST_STOP = false`
- Manifest에 `pleos.car.permission.NAVI_ROUTE_SEARCH` 추가 (경유지 추가 권한, 보호 수준 Normal)
- `PleosVoice.kt`에 LLM 추가: `initLlm()`, `generate(prompt) { text -> }`
- 테스트 화면에 버튼 3개 추가: **LLM 연결 (SERVER)**, **LLM 연결 (ON_DEVICE)**, **LLM 제안 문장 시험**

## 친구가 해 줄 것
1. **git pull** 받고 빌드되는지 확인. 오류 나면 캡처해서 공유.
2. **`demo_rec_1~3` 다시 만들기** (edge-tts)
   - 소리 내용이 `DemoSpeech.ANSWERS` 문장과 **글자 하나까지 같아야** 한다. 화면에 그 글자가 저장되어 뜨기 때문이다.
   1. "작년엔 호두과자만 먹었는데 올해는 인형뽑기도 또 했어! 호두과자는 역시 여기가 원조야"
   2. "줄이 진짜 길었는데 빵 먹으니까 다 괜찮아. 다음엔 할아버지가 아침 일찍 사 오신대"
   3. "호수가 바다만큼 넓어! 다음엔 유람선 타자. 엄마는 바람이 제일 좋았대"
3. **`demo_reaction_cheonan`이 "들렀다 가자"는 뜻의 대답인지 확인**
   - 지금 "응! 호두과자 사 먹고 가자!"로 가정하고 있다.
   - 시연에서는 글자를 안 띄우니까 뜻만 맞으면 된다. "응/좋아/가자" 같은 대답이면 OK.
4. 에뮬레이터 네비에 **목적지를 하나 찍어 두고** 천안 장면을 돌려서, 경유지가 실제로 들어가는지 확인. 테스트 화면의 네비 상태 줄을 보면 된다.

> `scripts/make_voices.sh`는 맥 전용이라(`say`, `afconvert`) 소리 파일 `v_tts_suggest_cheonan`, `v_stop_added`, `v_stop_skip`은 내가 만들어서 커밋할게.
